2. Validate the template with the official Domain Connect template editor/linter and obtain GoDaddy onboarding/approval. 3. Generate an RSA signing key of at least 2048 bits and keep its private PEM in a secret manager. Publish the corresponding SPKI public key at `<key-label>.<syncPubKeyDomain>` using Domain Connect's `p=1,a=RS256,d=...` TXT format. Split multiple public-key records with sequential `p` indexes as specified.
4. Configure `DOMAIN_CONNECT_PROVIDER_ID`, `DOMAIN_CONNECT_SERVICE_ID`, `DOMAIN_CONNECT_KEY_LABEL` (e.g. `_dcpubkeyv1`), `DOMAIN_CONNECT_PRIVATE_KEY` and a public HTTPS `DASHBOARD_ORIGIN`. Set `DOMAIN_CONNECT_APPROVED=true` only after GoDaddy approval and key publication. Defaults keep the integration unavailable with a manual-setup explanation.
5. Verify sandbox/partner fixtures first, then complete a real authorized consent on a test domain. The app checks GoDaddy nameservers, signs the exact URL-encoded query with RSA-SHA256, and uses a short-lived, single-use state bound to the signed-in user, organization, project and domain. A returned redirect never marks the domain verified: Check DNS remains authoritative.

The domain page's Automatic setup action redirects directly when enabled. When not onboarded it explains availability and offers manual setup. API credentials remain an explicitly advanced alternative. The callback strips state/error parameters after consumption, handles cancellation and rejects replay or another user's state.
